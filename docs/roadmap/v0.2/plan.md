# v0.2 — Skill Hardening

## Mission

Determine whether the first Eclipse skills produce bounded architect → worker → reviewer behavior on controlled fixtures and real repositories.

v0.2 is evaluation-driven and skills-first. Allowed changes are skill wording, references, protocol documents, adapter guidance, evaluation cases, and lightweight deterministic validation. Agent runtimes, schedulers, worktree or git engines, persisted workflow state, process managers, and migration systems are out of scope.

The release requires 10 controlled fixture families, at least 20 controlled cases, at least 5 pinned real repositories, and at least 30 qualifying real task runs. The real-task categories must include six bounded changes, six multi-file changes, five bug fixes, four refactors, three architecture-sensitive tasks, three parallelization candidates, and three review/correction cases.

Freeze the campaign before the v0.1 baseline. Preserve every failure, map each fix to a finding and regression case, and rerun the identical campaign. The skills must remain useful without Python tooling.
